# مساحة — موقع تأسيسي

نسخة أولية لموقع عربي باتجاه RTL، مبنية باستخدام React وVite، مع قاعدة بيانات PostgreSQL عبر Supabase.

## ما الموجود الآن؟

- صفحة رئيسية متجاوبة باللغة العربية.
- أقسام تعريفية ومميزات ونموذج تواصل.
- صفحة `/admin` لتسجيل الدخول وإدارة المقالات والرسائل.
- قاعدة بيانات Supabase مُنشأة ومفعّلة.
- مخطط قاعدة بيانات موثق في مجلد `supabase/migrations`.
- نشر أولي على Vercel.

> الاسم والنصوص الحالية مؤقتة. سنحدد هوية الموقع ومجاله ومحتواه في المرحلة التالية.

## التشغيل محليًا

1. ثبّت Node.js.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env.local`.
4. أضف عنوان مشروع Supabase ومفتاحه العام إلى متغيري البيئة:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
5. نفّذ `npm run dev`.

## قاعدة البيانات

مشروع Supabase الحالي اسمه `tay-space` والمنطقة هي Frankfurt (EU Central). تم تطبيق المخطط بالفعل؛ الملف `supabase/migrations/202611240001_initial_schema.sql` يوثق الجداول والسياسات المطبقة.

الجداول:
- `profiles`: بيانات الحسابات وأدوارها.
- `categories`: تصنيفات المحتوى.
- `articles`: المقالات والمسودات.
- `messages`: رسائل نموذج التواصل.
- `site_settings`: إعدادات الموقع.

سياسات RLS مفعلة على كل الجداول. مفتاح `publishable` مخصص للاستخدام في المتصفح؛ لا تضع مفتاح `service_role` أو أي مفتاح سري في الواجهة الأمامية أو مستودع GitHub.

## إدارة المحتوى والمواد التعليمية

- لوحة الإدارة متاحة من المسار `/admin` لحسابات الإدارة فقط.
- يمكن إدارة المقالات والمسودات، ورفع ملفات PDF والصور ومستندات Word والروابط، وتصنيف الموارد ونشرها أو إخفاؤها.
- يمكن إنشاء الامتحانات وإضافة أسئلة اختيار من متعدد وصح/خطأ وإجابة قصيرة وصور للأسئلة، وتحديد الدرجات والإجابات الصحيحة.
- محرر الموقع يحفظ نصوص الواجهة وصورها والأقسام المخصصة داخل `site_settings`، ويمكن معاينة التعديلات ثم نشرها.
- ملفات الموقع تحفظ في Storage bucket باسم `tay-assets`، والرفع والحذف محصوران بحسابات الإدارة عبر RLS.

## حسابات الطلاب وتسجيل الدخول

- ينشئ الطالب حسابًا باستخدام اسم مستخدم وكلمة مرور، دون إرسال رمز تحقق بالبريد.
- اسم المستخدم من 3 إلى 24 حرفًا إنجليزيًا صغيرًا أو رقمًا أو شرطة سفلية `_`.
- كلمة المرور لا تقل عن 8 أحرف، والحد الأعلى 72 حرفًا.
- تتم المصادقة عبر Supabase Edge Function باسم `username-auth`، ولا يُرسل مفتاح الخدمة إلى المتصفح.
- الحسابات التي أُنشئت سابقًا بالبريد وكلمة المرور احتفظت بكلمات مرورها. اسم المستخدم الأولي لها هو الجزء السابق لعلامة `@` من البريد، بعد تحويله إلى أحرف صغيرة واستبدال الرموز غير المدعومة بـ `_`.
- لا تتوفر حاليًا آلية استرداد كلمة المرور؛ لذلك يجب حفظها بأمان.

## تفعيل حساب الإدارة

1. أنشئ حسابًا عاديًا من صفحة `/account` أو استخدم حسابًا موجودًا.
2. من SQL Editor في Supabase، غيّر اسم المستخدم المقصود إلى مدير:

```sql
update public.profiles
set role = 'admin'
where username = 'YOUR_USERNAME';
```

3. افتح `/admin` وسجّل الدخول باسم المستخدم وكلمة المرور.

## نشر وظيفة المصادقة

- مصدر الوظيفة: `supabase/functions/username-auth/index.ts`.
- الإعداد `verify_jwt = false` مطلوب لأن التسجيل وتسجيل الدخول يبدآن قبل امتلاك جلسة مستخدم. تتحقق الوظيفة من بيانات الدخول عبر Supabase Auth وتعيد جلسة المستخدم عند نجاحها.
- ملف `supabase/config.toml` يحفظ هذا الإعداد حتى لا يعود التحقق الافتراضي من JWT ويمنع طلبات تسجيل الدخول.
- الجدول `username_signup_attempts` مخصص للخادم فقط؛ RLS مفعّل ولا توجد صلاحيات قراءة/كتابة للأدوار العامة أو للمستخدمين المسجلين.
- وظيفتا `start-exam` و`submit-exam` تتطلبان JWT صالحًا. يبدأ الخادم جلسة امتحان بوقت انتهاء ثابت، وتُحفظ النتيجة من خلال دالة داخلية لا يملك صلاحية تشغيلها إلا `service_role`.


## النشر

الموقع منشور على Vercel. متغيرا البيئة السابقان موجودان على بيئات Production وPreview وDevelopment. أمر البناء هو `npm run build` ومجلد الناتج `dist`.
